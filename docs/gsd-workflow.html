Sequence Diagram

The full per-phase pipeline traced from ROADMAP entry to opened PR, with the rationale for each stage's internal ordering.

Walkthrough

01 · Frame Each artifact must exist before plan-phase reads it. SPEC.md sets WHAT (most upstream), CONTEXT.md captures vision, AI-SPEC and UI-SPEC are specialty contracts (parallel branches), and mvp-phase mutates ROADMAP and triggers plan-phase — so it must be terminal in this stage.
02 · Plan plan-phase OR ultraplan-phase produces PLAN.md. review then runs against PLAN.md producing REVIEWS.md. plan-review-convergence wraps both in a loop — replan with feedback until no HIGH concerns remain.
03 · Execute execute-phase consumes verified PLAN.md, runs waves in parallel, emits commits + SUMMARY.md + VERIFICATION.md. autonomous is a meta-runner that re-runs Frame + Plan + Execute per phase.
04 · Verify Cheaper checks first. Automated audits (code-review, secure-phase, ui-review, eval-review) pre-screen the code → manual UAT (verify-work) on already-cleaned code → fill coverage gaps (validate-phase, add-tests) → auto-fix audit findings (audit-fix) → reflect (extract-learnings). verify-work may loop back to execute-phase --gaps-only.
05 · Ship pr-branch (filters out .planning/ commits) → ship (push branch, open PR with auto-generated body). Ship is final and requires the phase to be verified.

Sanity-check flag /gsd-audit-fix documents only --source <audit-uat>, and /gsd-audit-uat is explicitly milestone-level ("use before starting a new milestone to clear verification debt"). Strictly per-phase, audit-fix lives one level up. It is shown here because its character (find → fix → test → commit) belongs in the verify cluster, but drop it if you want pure per-phase fidelity.
