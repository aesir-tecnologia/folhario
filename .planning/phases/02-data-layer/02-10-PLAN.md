Create `02-10-SUMMARY.md` recording command outputs. The SUMMARY MUST contain these documented sections (the verifier asserts each is present):

1. **Production runtime guard for the auth.uid() shim.** Document the failure mode: in production, `scripts/check-rls.ts` queries `pg_namespace` for `nspname = 'auth'` and throws if absent. This prevents the CI-only `auth.uid()` shim from silently standing in for real Supabase auth. (Source: HIGH-1 in 02-REVIEWS.md.)

2. **Local Supabase config refresh requirement.** After editing bucket declarations in `supabase/config.toml`, developers MUST run `supabase stop && supabase start` for the new buckets to materialize. Plan 04's storage integration test fails with this exact instruction.

3. **INFRA-19 scoping note.** This phase covers the SERVER pipeline (multipart parsing, GPS rejection via `exifr`, sharp thumbnailing, size-limit enforcement at `MAX_UPLOAD_BYTES = 1_048_576`). The in-browser client compression path (`browser-image-compression` running in a real browser worker) is NOT exercised by Playwright in Phase 2. The first browser-side UAT for that path is deferred to a manual UAT step or to a phase that ships product UI for upload (Phase 3+). Phase 2 marks INFRA-19 done with this scoping caveat.

4. **Phase 4+ idempotency cleanup task.** `idempotency_keys` rows expire at `now() + 7 days` but Phase 2 has no worker to delete them. Add a Phase 4+ TODO: register an Inngest cron `cleanup.idempotency_keys` (daily) that runs `DELETE FROM idempotency_keys WHERE expires_at < now()`.

5. **CI rollback note.** If the integration-test job fails on a fresh DB after `pnpm db:setup`, the rollback path is: revert the failing migration commit on the PR branch, push to retrigger CI, and address the failure in a follow-up commit. The Phase 2 changes do not introduce destructive irreversible migrations — all DDL is additive (new tables, new policies, new indexes, new trigger conditional on auth.users presence).

6. **MB vs MiB reconciliation.** A single constant `MAX_UPLOAD_BYTES = 1_048_576` (1 MiB) lives in `src/shared/images/limits.ts`. The browser-image-compression API name `maxSizeMB: 1` (1 MB ≈ 0.954 MiB) is intentional — it produces files comfortably under the server boundary.

7. **Test JWKS source.** The deterministic E2E test JWKS lives at `tests/e2e/fixtures/test-jwks.ts` and is registered through `tests/e2e/global-setup.ts`. The positive-token Playwright subtest cannot silently skip; if globalSetup throws, the whole run aborts. (Source: HIGH-2 in 02-REVIEWS.md.)
