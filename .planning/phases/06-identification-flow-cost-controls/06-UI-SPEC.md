## Spacing Scale

Standard 8-point scale (multiples of 4). Inherit from project baseline — do not redefine tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, tight inline padding |
| sm | 8px | Inter-element gap inside card rows, thumbnail gap |
| md | 16px | Default element spacing, card internal padding |
| lg | 24px | Section padding, ModalSheet internal padding (matches existing ModalSheet `p-6`) |
| xl | 32px | Layout gaps, between card stack entries |
| 2xl | 48px | Major section breaks, capture guide → capture button gap |
| 3xl | 64px | Page-level top/bottom breathing room |

Exceptions:
- Capture button: 72px diameter circle (PRD §17 exception — only non-rounded-rect button geometry)
- Touch targets: minimum 44px × 44px for all interactive elements (WCAG 2.1 AA)
- Bottom-nav safe-area: `pb-safe-bottom` via `--spacing-safe-bottom: env(safe-area-inset-bottom)` (existing token)
- Focus ring: 3px Canopy @ 40% opacity, 2px offset, 8px corner radius (global, already set in globals.css)

## ConfidenceLadder Component Contract (UI-15)

New shared component at `src/shared/ui/confidence-ladder.tsx`. Caller passes `confidence: number` (0–1 raw). Component derives tier internally.

### Tier Thresholds (export as named constants `CONFIDENCE_THRESHOLDS`)

| Tier | Range | Internal constant |
|------|-------|------------------|
| High | ≥ 0.70 | `CONFIDENCE_HIGH = 0.70` |
| Medium | 0.40 – 0.69 | `CONFIDENCE_MEDIUM = 0.40` |
| Low | min_confidence – 0.39 | (below CONFIDENCE_MEDIUM) |

(`min_confidence` = 0.30 from `ProviderBudget` seed — values below this are filtered server-side and never reach the component)

### 4 Redundant Signals (all 4 must render in every tier — color is never sole signal)

| Signal | High | Medium | Low |
|--------|------|--------|-----|
| Bar fill width | 100% of track | ~65% of track | ~30% of track |
| Filled segments | 3 of 3 segments | 2 of 3 segments | 1 of 3 segments |
| Percentage label | `<n>%` in Calm Slate metadata style | `<n>%` in Calm Slate | `<n>%` in Calm Slate |
| SR label (aria-label on container) | `"Confiança alta, <n>%."` | `"Confiança média, <n>%."` | `"Confiança baixa, <n>%."` |

### Bar Colors

| Tier | Light fill | Dark fill |
|------|-----------|-----------|
| High | Canopy Green `#1F4D35` | Canopy Sprout `#6FAE8A` |
| Medium | Honey Amber `#D4A340` | Honey Lantern `#E8BC5E` |
| Low | Calm Slate `#5A6358` | Lantern Slate `#B8B0A5` |

Track (unfilled portion): Hairline Beige / Hairline Umber.

### Segments

3 equal-width pill segments separated by 4px gaps. Filled segments use the tier bar color. Unfilled segments use Hairline Beige / Hairline Umber. The bar is a continuous fill behind the segmented visual overlay (bar handles the accessible aria-valuenow; segments are decorative `aria-hidden`).

### Accessibility

- Outer wrapper: `role="img"` with computed `aria-label` as above.
- Segments: `aria-hidden="true"`.
- Track bar: `role="progressbar"` `aria-valuenow={Math.round(confidence * 100)}` `aria-valuemin="0"` `aria-valuemax="100"` `aria-label` identical to outer wrapper (belt-and-suspenders for SR traversal).
- `prefers-reduced-motion`: no animated fill transitions — render at final state immediately.

### State 1: Picker (Idle — Capture Guide)

The default state when the user lands on the Identify screen.

**Layout:**
- Capture guide always visible above the picker affordance (static, never dismissible)
- 3 illustration slots in a horizontal row: leaf icon + flower icon + whole-plant icon (Understory Sage line art, 1.5px Lucide family, 48px each)
- Guide caption beneath illustrations: `"Mais fotos melhoram a precisão"` — Plus Jakarta Sans 14px, Calm Slate, centered
- Capture button: 72px diameter circle, Canopy fill, Warm Ivory/Night Cream camera Lucide icon (20px), floats centered below guide
- Thumbnails strip: horizontal row beneath capture button — appears after first photo selected; each thumbnail 64×64px, 8px corner radius, 8px gap. Remove `[×]` button at 20px overlapping top-right of each thumbnail. `[+]` add-more affordance as a 64×64px dashed-border Hairline tile at the end of the strip (tap = triggers picker again)
- "Identificar" primary button: Plus Jakarta Sans 16px 600, Canopy fill, Ivory label, 48px tall, 8px radius — renders below thumbnails strip once ≥1 photo is selected; disabled (opacity 50%, pointer-events none) when no photos selected

**Copy:**
- Screen heading (Source Serif 4, 24px, 600): `"Identificar planta"`
- Guide caption: `"Mais fotos melhoram a precisão"`
- CTA: `"Identificar"`
- Thumbnail remove button `aria-label`: `"Remover foto"`
- Add-more tile `aria-label`: `"Adicionar mais fotos"`
- Capture button `aria-label`: `"Tirar foto ou escolher da galeria"`

**Interaction:**
- Tapping the capture button or `[+]` tile: first checks subscription status (paywall gate, State 9), then checks LGPD consent (consent modal, State 5), then opens native picker (multi-select)
- Picker returns 1..N photos → strip renders
- "Identificar" → submits multipart POST → transitions to State 2 (Loading)

### State 2: Loading

Triggered by "Identificar" tap. Cannot be cancelled (D-20 — no cancel button).

**Layout:**
- Hero heading (Source Serif 4, 32px, 600, Forest Ink/Moonpaper): `"Identificando sua planta…"` — centered
- Below heading: `<SkeletonGroup delay={300}>` wrapping 3 stacked `<Skeleton>` blocks simulating result cards (height 120px each, full width minus 32px margin, 8px radius, 16px gap between)
- Reduced-motion: SkeletonGroup still gates at 300ms; Skeleton renders static Hairline block (no shimmer) with 80ms fade-in — existing Skeleton behavior

**Copy:**
- Heading: `"Identificando sua planta…"`
- SR live region (`aria-live="polite"`, `aria-atomic="true"`): `"Identificação em andamento, por favor aguarde."` — injected on state entry
- No progress percentages, no stage labels, no timer

**Behavior:**
- Request runs server-side. If user navigates away, server completes and persists the row (IDENT-14). No in-flight restoration on return.
- On response: transitions to State 3 (Results), State 4 (Zero results), State 7 (Provider unavailable), or State 8 (Offline)
- On cap_hit during load (edge case — cap check is pre-flight, but handle defensively): transitions to State 6

### State 3: Results (Top-3 Cards)

3 result cards stacked vertically, equal visual weight (D-24 — no hero treatment for card #1).

**Layout:**
- Page heading (Source Serif 4, 24px, 600): `"Resultados"`
- Caption below heading (Plus Jakarta Sans 14px, 400, Calm Slate): `"Resultados ordenados pelo nível de confiança"`
- 3 cards, vertical stack, full-width minus 32px margin (16px each side), 16px gap
- Each card (Warm Ivory/Embered Surface bg, 8px radius, 16px padding):
  - Row: square thumbnail 64×64px (8px radius) | Column: common name (PT) + scientific name + ConfidenceLadder + CTA
  - Common name: Plus Jakarta Sans 16px, 600, Forest Ink/Moonpaper
  - Scientific name: `<span lang="la"><em>Genus species</em></span>`, Plus Jakarta Sans 14px, 400, Calm Slate/Lantern Slate, italic
  - ConfidenceLadder component directly below scientific name
  - CTA button (full-width, secondary variant): `"Adicionar à minha estante"`
  - Tap anywhere on card body → same action as CTA tap
- Below card stack, tertiary text link: `"Não é nenhuma destas?"` → opens manual-correction input (State 3b)
- If thumbnail missing/errored: 64×64px Hairline placeholder with Understory Sage plant icon (20px)

**State 3b: Manual Correction Inline (under top-3)**
- Text input expands below the "Não é nenhuma destas?" link
- Label: `"Nome da planta"` (Plus Jakarta Sans 14px, 600)
- Placeholder: `"Ex: Monstera deliciosa"`
- Submit button (secondary, full-width): `"Salvar correção manual"`
- Note beneath input (14px, Calm Slate): `"Se não encontrarmos o guia de cuidados, avisaremos o time para incluir."`

**Interaction:**
- Tapping "Adicionar à minha estante" or card body → opens selection confirmation sheet (State 3c)
- "Não é nenhuma destas?" → expands State 3b inline; does not navigate away
- Submitting manual correction → closes inline form, shows Sonner success toast, navigates to catalog

**State 3c: Selection Confirmation Sheet**
- `<ModalSheet>` title: `"Adicionar à minha estante"`
- Close label: `"Cancelar"`
- Content:
  - Name field (text input, pre-filled with species common name pt-BR): label `"Nome da planta"`, editable
  - Location field: `<Combobox>` (reuse Phase 5 D-08 `<LocationCombobox>`) — label `"Localização"`, optional
  - Notes field (textarea): label `"Notas"` (optional), placeholder `"Observações sobre esta planta…"`
  - Primary button (full-width): `"Confirmar"`
- On confirm → POST plant creation → navigate to `/catalog/{plantId}` on success
- Sheet `onCloseAutoFocus`: return focus to the card's CTA that opened it

### State 7: Provider Unavailable

All providers exhausted (internal reasons: `cost_ceiling_reached`, `breaker_open`, `timeout`, `invalid_response` — NONE of these strings appear in user-facing copy per COST-07 and PRD §5 closed registry).

**Layout:**
- `<AlertCircleIcon>` 32px, Overdue Rust/Overdue Copper, centered
- Heading (Source Serif 4, 24px, 600): `"Identificação temporariamente indisponível"`
- Body (16px, 400): `"Tente novamente mais tarde. Suas fotos foram salvas e estão prontas para nova tentativa."`
- Primary button (full-width): `"Tentar novamente"` — available; restores to State 1 with photos retained in IndexedDB (per IDENT-12)
- Tertiary text link: `"Adicionar manualmente"`

**Note:** This state covers `provider_unavailable` 503 AND `timeout` 504. From the user's perspective, the copy is identical — there is no UI distinction between a timeout and a breaker-open. Do not surface the HTTP status code or the internal reason.

**Note:** "Suas fotos foram salvas" requires the photo blobs to be held in IndexedDB while the user is on this screen (IDENT-12). On page reload / navigation away, photos are no longer retained — copy must not promise permanent retention.

**Note:** Copy above is an initial draft — founder reviews.

### State 8: Offline

### State 10: Validation Failed (GPS rejection)

Server rejected the upload because GPS EXIF tags were detected (IDENT-16). Shown as an inline error, not a full-state replacement (client-side stripping is the primary defense; this is the edge case).

## Identification History Screen (UI-12)

### Detail View

Full-record view for a single identification.

**Layout (success row):**
- Photo strip (all photos, horizontal scroll, 80×80px, 4px radius)
- Date + provider (14px, Calm Slate): `"dd/MM/yyyy HH:mm · via [provider display name]"` — provider display name = `"Plant.id"` or `"OpenAI compat"` (never internal IDs)
- Heading: `"Resultados"` (section label, uppercase, 14px, 600)
- Result cards (read-only version of State 3 cards, no "Adicionar" CTA)
- Selected result highlighted with `<CheckCircleIcon>` 18px Canopy Green + label `"Selecionada"` beneath the card
- Manual correction block (if `manual_correction` set): `"Correção manual: [value]"`
- Re-associate action (tertiary button or text link): `"Associar a uma planta do catálogo"` → triggers re-associate flow (BottomSheet with catalog plant picker)

**Layout (failed row):**
- Photo strip (if photos exist)
- Date + status badge (Overdue Rust)
- Body: `"Identificação não concluída."` + user-facing failure copy (mapped from internal reason per table above)
- No result cards

### Re-associate Flow

Triggered from Detail View "Associar a uma planta do catálogo" CTA.

- `<ModalSheet>` title: `"Associar ao catálogo"`
- Content: searchable plant list (user's catalog) or "criar nova planta" option
- On selection: PATCH `Identification.plant_id` → success toast + close sheet
- On "criar nova planta": navigates to plant creation, pre-filling from identification data

## Error Code → UI State Mapping

| HTTP error / internal reason | Public code shown to user | UI State | Internal reason persisted? |
|-----------------------------|--------------------------|----------|---------------------------|
| `consent_required` 403 | — (modal shown before request fires) | State 5 (Consent Modal) | No |
| `cap_hit` 429 | — (cap check pre-flight) | State 6 (Cap Hit variants) | No |
| `provider_unavailable` 503 | — | State 7 | Yes (internal) |
| `timeout` 504 | — | State 7 | Yes (internal) |
| `validation_failed` 400 (GPS) | — | Sonner toast (State 10) | No |
| `subscription_required` 402 | — | State 9 (Paywall Modal) | No |
| `cost_ceiling_reached` (internal) | `provider_unavailable` | State 7 | Yes |
| `breaker_open` (internal) | `provider_unavailable` | State 7 | Yes |
| `invalid_response` (internal) | — (triggers fallover; not user-visible unless all fail) | State 7 if all fail | Yes |

**Critical constraint:** The strings `cost_ceiling_reached`, `breaker_open`, `invalid_response` MUST NEVER appear in any user-visible UI element, toast, error boundary, or network response body. This is enforced by COST-07 and the PRD §5 closed registry. The executor must add a snapshot test asserting this.

|-------------|----------------|
