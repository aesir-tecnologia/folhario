<threat_model>
T-02-20 GPS leakage: EXIF GPS can be stored despite client-side strip. Mitigation: server parses uploaded bytes with exifr and rejects before adapter upload.
T-02-21 service-role exposure: Supabase service role in browser would bypass RLS. Mitigation: storage adapter is server-only and route uses signed URL helpers.
T-02-22 native package runtime mismatch: sharp fails on edge runtime. Mitigation: upload route exports `runtime = "nodejs"` and an integration smoke test calls `sharp().metadata()` on a 1x1 fixture so any "Could not load the sharp module" failure surfaces in CI before the route is exercised.
T-02-39 size-limit drift between client and server: if `maxSizeMB: 1` (~0.954 MiB) and server reject threshold (1 MiB = 1_048_576 bytes) drift further apart, files compressed to ~1 MB on the client may still hit a server reject if a future server constant is set to 1_000_000 instead. Mitigation: server uses `MAX_UPLOAD_BYTES = 1_048_576` (1 MiB) as the single boundary; client target is 1 MB which is strictly under 1 MiB so the boundary is never tight; both come from `src/shared/images/limits.ts`.
</threat_model>
