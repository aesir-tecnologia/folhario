## State Machine — Identify Screen

The Identify screen is a single route (`/identify`) with conditional rendering across 13 distinct UI states. State transitions are managed client-side; the route handler dictates server-driven outcomes via error codes.

| # | State | Trigger | Composition | Bottom-nav | Capture guide |
|---|-------|---------|-------------|------------|---------------|
| 1 | `idle` | Initial load, no consent gate active, online, not read-only | `<CaptureGuide>` + camera button (Phase 3 `<CaptureButton>`) + gallery button (secondary) | Visible | Visible |
| 2 | `consent-modal` | User taps capture/gallery button AND no `identification_third_party` ConsentLog exists | LGPD consent modal overlays state 1; capture guide remains visible behind scrim | Visible | Visible (behind scrim) |
| 3 | `picking` | User dismissed consent modal mid-flow OR is between selections | Same as `idle`. (Internal state for the route — UX-equivalent to `idle`.) | Visible | Visible |
| 4 | `photos-selected` | After file-picker confirm with ≥1 photo | `<PhotoStrip>` replaces `<CaptureGuide>` middle area; capture guide hint card persists at top; "Identificar" primary CTA appears bottom (sticky-bottom above nav with safe-area inset) | Visible | Hint card only |
| 5 | `uploading` | User taps "Identificar"; client-side compression + EXIF strip in flight | `<Skeleton>` block (4:5 ratio) replaces photo strip; progress text "Enviando fotos…" Plus Jakarta Sans 16 Calm Slate | Visible | Hidden |
| 6 | `identifying` | After upload completes, while route handler awaits provider | `<Skeleton>` block + progress text "Identificando sua planta…" — replaces upload state; identical visual but different copy | Visible | Hidden |
| 7 | `results` (3 confidence tiers) | `POST /v1/identifications` returns ≥1 result above `min_confidence` | Vertical stack of `<IdentificationResultCard>` (1–3 cards) + "Não é nenhuma delas" tertiary text link below cards. Confidence tier (high / medium / low) is per-card; a single result list may mix all three tiers. | Visible | Hidden |
| 8 | `zero-results` | Provider returned 0 results above `min_confidence` (Identification row still persisted with `status=success`, empty `results`) | `<EmptyState>` composer: Sage line-art "no-match" sprite + Source Serif headline "Hmm, não conseguimos identificar desta vez." + Calm Slate hint "Tente com mais fotos ou de ângulos diferentes." + primary CTA "Tentar novamente" + tertiary text link "Adicionar manualmente" | Visible | Hidden (empty-state owns the visual) |
| 9 | `cap-hit` | Server returned `cap_hit` 429 | `<CapHitChip>` at top + headline "Você atingiu o limite de identificações de hoje." + reset-time hint ("Próximo limite em {resetTime}", pt-BR relative time via `Intl.RelativeTimeFormat`) + tertiary text link "Adicionar manualmente". **NO retry button** (per AC-ID-009). | Visible | Hidden |
| 10 | `provider-unavailable` | Server returned `provider_unavailable` 503 | `<InlineError>` (Phase 3): cause "Identificação temporariamente indisponível." + recovery "Tente novamente em alguns minutos." + retry button "Tentar novamente" (Canopy primary) + tertiary text link "Adicionar manualmente". Selected photos retained client-side (`<PhotoStrip>` persists below the inline error so user can re-submit without re-picking). | Visible | Hidden |
| 11 | `timeout` | Server returned `timeout` 504 OR client AbortController fires at 48 s | `<InlineError>`: cause "A identificação demorou mais que o esperado." + recovery "Tente novamente com fotos mais nítidas." + retry button "Tentar novamente" + tertiary text link "Adicionar manualmente". Same photo-retain behavior as state 10. | Visible | Hidden |
| 12 | `offline` | `useOnlineStatus()` returns `false` | `<EmptyState>`: Sage line-art "wifi-off" sprite + Source Serif headline "Identificação requer conexão à internet." + Calm Slate hint "Volte aqui quando sua conexão voltar." + NO primary CTA (the Phase 3 `<EmptyState>` "exactly one CTA" rule yields to PRD §16 line 773 which provides no CTA for this state — single-CTA exception logged). The static `<CaptureGuide>` STAYS VISIBLE ABOVE the empty state so users can study the photo guide while offline (CONTEXT D-24). | Visible | Visible (above empty state) |
| 13 | `read-only-paywall` | `useSubscription()` returns `{readOnly: true}` AND user taps capture/gallery button | Radix Dialog (NOT ModalSheet — CONTEXT D-25 explicit, mirrors PRD §10 paywall pattern): headline "Reative sua assinatura para identificar novas plantas." + body Calm Slate "Sua assinatura está pausada. Reative para retomar identificações." + primary CTA "Ver assinatura" linking to `/settings/subscription` (Phase 10 destination; Phase 6 lands placeholder) + tertiary text link "Cancelar". `dismissOnScrim={false}`, `dismissOnEsc={true}`. | Visible | Hidden (Dialog overlays) |

**Result-selection sheet** (state 7 follow-up) is a separate `<ModalSheet>` triggered by tapping a result card — not a state of the page itself. Documented in § 4 below.

**A11y across states:** Each state transition fires a `role="status"` announcement of the headline copy via an offscreen `aria-live="polite"` region. State transitions update document title (`Identificar — {state-label}`) so screen readers mark the change.

## Composed Primitives (NEW in Phase 6)

### 1. `ConfidenceLadder` — UI-15 centerpiece (PRD §17 lines 866–872)

The honest-AI primitive. Combines four redundant signals so confidence is never carried by color alone. **Banned: any rendering with fewer than four cues.**

**File:** `src/shared/ui/confidence-ladder.tsx`

**Props:**
```ts
type ConfidenceLadderProps = {
  confidence: number; // 0..1, normalized at render
  segments?: number; // default 5; PRD §17 implies 5-segment bar
};
```

**Tier mapping:**

| Tier | Range | Bar fill (light / dark) | Filled segments | SR label |
|------|-------|--------------------------|-----------------|----------|
| High | ≥ 0.70 | Canopy Green `#1F4D35` / Canopy Sprout `#6FAE8A` | 5 of 5 (or `Math.round(confidence * 5)` capped at 5) | `Confiança alta, {n}%` |
| Medium | 0.40–0.6999 | Honey Amber `#D4A340` / Honey Lantern `#E8BC5E` | 3 of 5 (or `Math.round(confidence * 5)`) | `Confiança média, {n}%` |
| Low | min_confidence (0.30 default) – 0.3999 | Calm Slate `#5A6358` / Lantern Slate `#B8B0A5` | 1 of 5 (or 2 — per `Math.round`) | `Confiança baixa, {n}%` |

**Visual:**

- **Bar:** 6 px tall, full width of the parent slot (right of result-card thumbnail; ~140 px in the result card layout). Background Hairline Beige `#E8E1D0` / Hairline Umber `#3A332B`. Border-radius 3 px. Inner 5 segment ticks rendered as 1.5 px Hairline Beige / Umber vertical separators at 20% / 40% / 60% / 80% (4 separators producing 5 segments).
- **Fill:** Same height as bar, left-aligned, width `confidence * 100%`, border-radius 3 px (rounds left only — right edge is sharp until full). Color from tier mapping above.
- **Percentage label:** Plus Jakarta Sans 13 / 18 weight 600 Forest Ink / Moonpaper, formatted `Math.round(confidence * 1000) / 10`% (max 1 decimal — no fake precision; CONTEXT key-constraint 6). Right of bar, 8 px gap. When percentage is whole (e.g. 70 %), no decimal renders ("70 %" not "70.0 %").
- **Tier text** (additional cue, alongside the four core signals): Plus Jakarta Sans 14 / 20 weight 500 Calm Slate, format `Pode ser…` (medium + low tiers, per PRD §17 lines 871–872) OR no prefix (high tier, common name renders directly). Rendered ABOVE the common name in the parent result card.
- **SR-only label:** `<span class="sr-only">{tierLabel}</span>` rendered inside the bar element, format from table above.

**Reduced motion:** Bar fill animates from 0% → target width over `springs.primary` (~240 ms) on first render. `prefers-reduced-motion: reduce` → instant render at target width.

**Banned:** Color-only state communication (always 4 cues: bar fill color + segment count + numeric % + SR label). Bar fill in any color other than the three tier mappings. Segments count other than 5. Percentage rendered with `>1` decimal place.

**axe gate:** ConfidenceLadder rendered at all three tiers MUST pass axe-core in light + dark themes + reduced-motion variant. Plan ships these tests.

### 3. `PhotoStrip` — Multi-photo selection (CONTEXT D-14 + `<specifics>` line 224)

After camera/gallery selection, selected photos appear as a horizontal scroll strip. **Max 5 photos per identification** (CONTEXT D-14).

**File:** `src/shared/ui/photo-strip.tsx`

**Props:**
```ts
type PhotoStripProps = {
  photos: Array<{ id: string; previewUrl: string }>;
  onRemove: (id: string) => void;
  onAddMore: () => void;
  maxPhotos?: number; // default 5
};
```

**Layout:** Horizontal `flex` container, 8 px gap, `overflow-x: auto`, `scroll-snap-type: x mandatory`. Padding 16 px horizontal so first/last tile aligns with page gutter.

**Tile (per photo):**

- 56 × 56 px square, 8 px radius, photo as `<img>` `object-fit: cover` from local `URL.createObjectURL` preview (CONTEXT D-14).
- Top-right corner: 20 × 20 px circular tap target with Lucide `X` 16 px stroked icon, Urgent Poppy `#C73E1D` / Urgent Blossom `#E8593A` color, Warm Ivory / Embered Surface bg @ 90 % opacity, 1.5 px Urgent Poppy / Blossom stroke. Tap → `onRemove(id)`.
- Per PRD §17 destructive-color reservation: this is a per-photo destructive micro-action (removes the photo from the upcoming submission), so Urgent Poppy is **in-scope**. Stripe red is NOT used for "general error" or styling here.

**"Adicionar mais" tile** (when `photos.length < maxPhotos`):

- 56 × 56 px square, 8 px radius, Hairline Beige / Hairline Umber 1.5 px dashed stroke, Lucide `Plus` 20 px Canopy Green / Canopy Sprout centered. Tap → `onAddMore()` (re-opens picker).
- Hidden when `photos.length === maxPhotos`.

**Count badge:**

- Top-right of the strip container (16 px from edge, 8 px from top), Plus Jakarta Sans 12 / 16 weight 600 Calm Slate / Lantern Slate, format `{n}/{max}` ("3/5"). Pure numeric, no i18n needed.

**A11y:**

- Strip container `role="list"` `aria-label="Fotos selecionadas para identificação"`.
- Each tile `role="listitem"`, has `aria-label="Foto {n} de {total}"`.
- Remove button `aria-label="Remover foto {n}"`.
- Count badge `aria-live="polite"` so additions/removals announce.

**Banned:** Drag-to-reorder in MVP (Claude's discretion narrowed: order = chronological selection; provider doesn't care). Tap-to-preview on tile (the strip is a queue, not a gallery — Lightbox is for catalog photos, not pending uploads).

### 4. `IdentificationResultCard` — Confidence result card (PRD §17 lines 943–945, CONTEXT D-16 + D-17)

- **Top-right:** `<ConfidenceLadder confidence={result.confidence} />` — bar + percentage label inline. Width ~140 px. Vertically centered against the thumbnail.
- **Below thumbnail + ladder row** (12 px gap):
  - Tier prefix (medium / low only): Plus Jakarta Sans 14 / 20 weight 500 Calm Slate `Pode ser…` (PRD §17 line 871–872). Hidden for high tier.

**A11y (PRD §17 line 945 — single utterance):**

- Card `role="button"`, `tabIndex={0}`, Enter / Space activates `onSelect`.

**Reveal motion:** 60 ms cascade per card (results stack) — opacity 0 → 1 + translateY 8 px → 0 (Phase 3 motion contract). Reduced motion: instant 120 ms opacity fade for the whole stack.

### 6. LGPD Consent Modal (CONTEXT D-09 + `<specifics>` line 220 + key-constraint 5)

Surfaces on user's first identify attempt (no prior `identification_third_party` ConsentLog row). Uses Phase 3 `<ModalSheet>` with **dismissibility override** per Conflicts Resolved.

**Override props (Phase 6 LGPD-only):**

```ts
<ModalSheet
  dismissOnScrim={false}   // PRD §17 line 1132 — critical modals can't be scrim-dismissed
  dismissOnEsc={false}     // ESC ambiguous as consent ack; user MUST commit explicitly
  showCloseButton={false}  // No "Fechar" affordance — only the two CTAs end the flow
/>
```

(If `<ModalSheet>`'s current API doesn't expose these props, Phase 6 plan extends the primitive with these named props as a default-true additive change. No behavior change for any other consumer — Phase 5 sheets keep current dismissibility.)

**Slot composition:**

| Slot | Component | i18n key | pt-BR copy |

## Banned Patterns (Phase 6 specific — additions to Phase 3 catalog)

- **NO circular spinners** in `uploading` / `identifying` states. Skeleton shimmer + progress text only (Phase 3 D-27 + CONTEXT D-15 — overrides PRD §16 line 767 wording).
- **NO confidence percentage with > 1 decimal place.** "70 %" or "65.4 %" — never "65.43 %" or "65.4321 %" (CONTEXT key-constraint 6 — no fake precision).
- **NO color-only confidence signal.** Always 4 cues (bar fill + segments + numeric % + SR label). Phase 3 line 449 + UI-15 enforce.
- **NO Trust Teal as a button fill or panel background.** Trust Teal is reserved for "Gerado por IA" chip stroke + label (and the LGPD strip mentioned in PRD §17, owned by Phase 11).
- **NO Honey Amber outside the confidence-bar fill.** PRD §17 line 842 explicitly forbids text/borders/outlines.
- **NO Urgent Poppy as a generic error fill.** It's reserved for toxicity (Phase 7) + destructive confirms (Phase 5 plant delete) + the per-photo remove-X micro-action (Phase 6 multi-photo strip). NOT for "identification failed" headlines.
- **NO retry button on cap-hit state** (AC-ID-009 explicit). Manual-entry text link only.
- **NO species names in PostHog properties.** Privacy + abstraction.
- **NO photo URLs in Sentry breadcrumbs or PostHog properties.** Phase 1 D-22 already scrubs `photo_url`; Phase 6 preserves request-body drop on `/api/v1/identifications/*` per Phase 1 SC-4.
- **NO emoji anywhere in identify flow copy.** PRD §17 emoji ban.
- **NO mid-session auto-reload** of the identify page. State machine is client-managed.
- **NO `<Lightbox>` on the multi-photo strip** during selection. Lightbox is for the catalog photo journal (post-association). Pending uploads are a queue, not a gallery.
- **NO scrim-dismiss on LGPD consent modal or read-only paywall Dialog.** Both override Phase 3 ModalSheet default per Conflicts Resolved table.
