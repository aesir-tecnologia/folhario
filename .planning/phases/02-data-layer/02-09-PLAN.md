<threat_model>
T-02-23 diagnostic route exposure: a diagnostics route can become an unauthenticated write surface. Mitigation: protected by `requireApiUser`; missing bearer returns 401.
T-02-24 route-discovery regression: using `_diagnostics` would silently 404. Mitigation: implement `/diagnostics/consent` and test real HTTP with Playwright.
T-02-25 duplicate consent writes: retries can create duplicate ConsentLog rows. Mitigation: POST is wrapped in DB-backed Idempotency-Key handling.
T-02-40 silent E2E skip on missing JWKS: a `test.skip` path on "JWKS empty or unreachable" turns the only positive-auth real-HTTP signal into a no-op. Mitigation: E2E global setup constructs a deterministic local key set via `jose.generateKeyPair` + `createLocalJWKSet`, exposes the JWKS to the running Next server through an env-var-pointed test endpoint OR the AuthAdapter factory injection from Plan 07; the positive subtest asserts a 201 was returned (not a generic "ok or skipped"); if setup cannot construct keys or the AuthAdapter cannot be configured, the WHOLE E2E run fails before any test runs. No `test.skip` is allowed on the valid-token subtest.
T-02-41 divergent test-JWT helpers across suites: Plan 07 (wave 5) and Plan 09 (wave 6) each implementing their own `generateKeyPair`-based test JWT helper would create two parallel signing surfaces that drift over time (different `kid`, different `alg`, different claim shape), masking auth bugs in one suite while passing in the other. Mitigation: a single helper at `tests/e2e/fixtures/test-jwks.ts` is the source of truth; Plan 09 Task 3 refactors `tests/integration/auth-jwt.integration.test.ts` to import from it and asserts (via word-boundary regex on the import path) that the file contains no duplicate `generateKeyPair` invocation.
</threat_model>
