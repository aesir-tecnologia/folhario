Step 3 — Create `scripts/sync-supabase-env.sh`:

```bash
#!/usr/bin/env bash
# scripts/sync-supabase-env.sh (D-18, R-3)
# Parses `supabase status -o env` output -> writes .env.local. NEVER modifies .env.
# Derives DATABASE_POOL_URL from DATABASE_URL (locally identical; prepare=false posture).
set -euo pipefail

# Fail fast if Docker is not available (supabase start depends on it).
if ! docker info >/dev/null 2>&1; then
  echo "ERROR: Docker daemon unreachable. Start Docker Desktop then retry." >&2
  exit 1
fi

OUT=.env.local
TMP="$OUT.tmp"

# Map Supabase CLI output keys -> PRD §20 variable names.
pnpm supabase status -o env \
  --override-name api.url=NEXT_PUBLIC_SUPABASE_URL \
  --override-name anon_key=NEXT_PUBLIC_SUPABASE_ANON_KEY \
  --override-name service_role_key=SUPABASE_SERVICE_ROLE_KEY \
  --override-name db.url=DATABASE_URL \
  > "$TMP"

# Derive DATABASE_POOL_URL from DATABASE_URL (locally Supabase does not run Supavisor).
DB_URL=$(grep '^DATABASE_URL=' "$TMP" | head -n1 | cut -d= -f2-)
if [ -z "$DB_URL" ]; then
  echo "ERROR: supabase status did not emit DATABASE_URL. Is 'pnpm db:start' running?" >&2
  rm -f "$TMP"
  exit 2
fi
echo "DATABASE_POOL_URL=$DB_URL" >> "$TMP"

# Add header comment.
{
  echo "# Auto-generated by scripts/sync-supabase-env.sh — do not edit by hand."
  echo "# Re-run 'pnpm db:sync-env' after 'pnpm db:start' or 'pnpm db:reset'."
  cat "$TMP"
} > "$OUT"
rm -f "$TMP"

echo "Wrote $OUT"
```

```typescript
// tests/integration/postgres-connection.integration.test.ts
// INFRA-26 + CLAUDE.md C-05 — postgres-js with { prepare: false } posture
// Runs against CI `postgres:17-alpine` service container (Plan 08) or local Supabase stack.
// Skips if DATABASE_POOL_URL absent. REFUSES cloud Supabase hostnames (Action 15).

import { describe, it, expect, afterAll } from "vitest";
import postgres from "postgres";

const dbUrl = process.env.DATABASE_POOL_URL;

// Action 15: prevent accidental integration runs against cloud Supabase databases.
// Any URL matching `supabase.co` triggers a hard throw BEFORE any connection is opened.
if (dbUrl && /supabase\.co/.test(dbUrl)) {
  throw new Error(
    "Refusing to run integration tests against cloud Supabase (supabase.co in DATABASE_POOL_URL). " +
      "Integration tests target local Supabase (pnpm db:start) or CI postgres:17-alpine only.",
  );
}

describe.skipIf(!dbUrl)("INFRA-26 local Postgres reachable via DATABASE_POOL_URL", () => {
  const sql = postgres(dbUrl!, {
    prepare: false, // Supavisor transaction-mode compat (locally harmless — C-05)
    max: 1,
    idle_timeout: 5,
  });

  afterAll(async () => {
    await sql.end({ timeout: 5 });
  });

  it("SELECT 1 succeeds", async () => {
    const rows = await sql`SELECT 1 AS one`;
    expect(rows[0]?.one).toBe(1);
  });

  it("Postgres major version is >=15 (any version; Phase 2 tightens to 17)", async () => {
    const rows = await sql<{ server_version_num: string }[]>`SHOW server_version_num`;
    const versionNum = Number(rows[0]?.server_version_num ?? "0");
    expect(versionNum).toBeGreaterThanOrEqual(150000);
  });
});
```

Rationale for lenient version check: locally Supabase pins Postgres 17 (via `supabase/config.toml`) and CI uses `postgres:17-alpine`, so both paths are 17+. Phase 2 tightens the check to `>= 170000` when schema work lands.
