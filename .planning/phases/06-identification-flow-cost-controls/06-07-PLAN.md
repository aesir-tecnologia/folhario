<objective>
TDD the circuit breaker state-machine repository. The breaker is the second of two cost-control layers (the first being the daily ceiling). It opens after a configurable run of failures, cools down for 60 seconds, transitions to half-open admitting ONE request, then either closes (on success) or re-opens (on failure).

Per RESEARCH Open Question 1, half-open concurrency is resolved via the `in_flight_at TIMESTAMPTZ` column added in plan 06-01 (rather than expanding the state CHECK enum to include `'in_flight'`). The optimistic-UPDATE pattern is `UPDATE ... SET state='half_open', in_flight_at=NOW() WHERE state='open' AND in_flight_at IS NULL AND opened_at < NOW() - INTERVAL '60 seconds'`. If two concurrent half-open transitions happen, only one row is updated (Postgres UPDATE is atomic at the row level); the loser sees `state='half_open' AND in_flight_at IS NOT NULL` and the router treats it as 'open'.

Purpose: COST-08 (state transitions), IDENT-15 (`invalid_response` → recordFailure). The router (06-06) calls these helpers; the use-case (06-08) does not directly.

Output: ~120-line repository file + ~250-line integration test file covering state transitions, the 10-minute window reset, and the half-open in-flight race.
</objective>

    4. Closed → first failure: state remains 'closed', consecutive_failures=1, last_failure_at set, opened_at NULL
    5. Closed + 4 prior failures within 10 min → 5th failure opens the breaker: state='open', consecutive_failures=5, opened_at = NOW(), last_failure_at = NOW()
    6. Closed + 4 prior failures, but last_failure_at > 10 min ago → 5th failure resets the counter to 1 (NOT 5); state remains 'closed' (the window expired; this counts as the start of a new run)
    7. Half-open → recordFailure: state='open', consecutive_failures=1 (failure during half-open is a single-step re-open; we don't count it as the 5th of an old run); opened_at = NOW(); in_flight_at = NULL (cleared)
    8. Open → recordFailure (defensive): state stays 'open'; consecutive_failures increments; opened_at NOT updated (preserve original open time)

    **recordSuccess:**
    9. Closed → recordSuccess: no-op (state='closed', counters unchanged); idempotent
    10. Half-open → recordSuccess: state='closed', consecutive_failures=0, opened_at=NULL, in_flight_at=NULL
    11. Open → recordSuccess (defensive — should not happen, but if it does): state='closed', counters cleared

    **transitionToHalfOpen (the optimistic-UPDATE guard):**
    12. Open + opened_at > 60s ago + in_flight_at IS NULL → transitions to half_open; in_flight_at = NOW(); UPDATE returns rowCount=1
    13. Open + opened_at < 60s ago → cooldown not elapsed; UPDATE returns rowCount=0 (no transition)
    14. Two concurrent transitionToHalfOpen calls — Promise.all on independent connections, both targeting the same opened breaker → exactly ONE returns rowCount=1, the other returns rowCount=0 (proving the in_flight_at guard prevents double-transition)

    ```typescript
    // src/contexts/identification/infrastructure/db/circuit-breakers.ts
    import { sql, and, eq } from "drizzle-orm";
    import { type DbClient } from "@shared/db/client";
    import { type TransactionalDb } from "@shared/db/unit-of-work";
    import { providerCircuitBreakers } from "@contexts/identification/infrastructure/db/schema";

    type BreakersDb = DbClient | TransactionalDb;

    export type CircuitBreakerRow = typeof providerCircuitBreakers.$inferSelect;

    const FAILURE_WINDOW_INTERVAL = sql`INTERVAL '10 minutes'`;
    const COOLDOWN_INTERVAL = sql`INTERVAL '60 seconds'`;
    const FAILURE_OPEN_THRESHOLD = 5;

    export async function findByProvider(db: BreakersDb, provider: string): Promise<CircuitBreakerRow | null> {
      const [row] = await db.select().from(providerCircuitBreakers).where(eq(providerCircuitBreakers.provider, provider)).limit(1);
      return row ?? null;
    }

    /**
     * Atomic state transition: if last_failure_at is within the 10-min window AND state='closed',
     * increment counters; if count crosses FAILURE_OPEN_THRESHOLD, open the breaker.
     * If outside window, reset to count=1 (new run starts).
     * Half-open → re-open immediately; opened_at = NOW(); in_flight_at = NULL.
     * Open → preserve opened_at, increment counter (defensive idempotency).
     *
     * Implementation: single UPDATE with CASE-WHEN expressions for transactional atomicity.
     */
    export async function recordFailure(db: BreakersDb, provider: string): Promise<CircuitBreakerRow> {
      const rows = await db.execute<CircuitBreakerRow>(sql`
        UPDATE provider_circuit_breakers
        SET
          state = CASE
            WHEN state = 'half_open' THEN 'open'
            WHEN state = 'closed' AND (
              last_failure_at IS NULL
              OR last_failure_at < NOW() - ${FAILURE_WINDOW_INTERVAL}
              OR consecutive_failures + 1 < ${FAILURE_OPEN_THRESHOLD}
            ) THEN 'closed'
            WHEN state = 'closed' AND consecutive_failures + 1 >= ${FAILURE_OPEN_THRESHOLD} THEN 'open'
            ELSE state
          END,
          consecutive_failures = CASE
            WHEN state = 'half_open' THEN 1
            WHEN state = 'closed' AND last_failure_at IS NOT NULL AND last_failure_at < NOW() - ${FAILURE_WINDOW_INTERVAL} THEN 1
            ELSE consecutive_failures + 1
          END,
          opened_at = CASE
            WHEN state = 'half_open' THEN NOW()
            WHEN state = 'closed' AND consecutive_failures + 1 >= ${FAILURE_OPEN_THRESHOLD}
              AND (last_failure_at IS NULL OR last_failure_at >= NOW() - ${FAILURE_WINDOW_INTERVAL})
              THEN NOW()
            WHEN state = 'open' THEN opened_at  -- preserve
            ELSE opened_at
          END,
          last_failure_at = NOW(),
          in_flight_at = NULL,
          updated_at = NOW()
        WHERE provider = ${provider}
        RETURNING *
      `);
      const r = rows[0];
      if (!r) throw new Error(`circuit_breakers.recordFailure: no row for provider=${provider}`);
      return r as CircuitBreakerRow;
    }

    export async function recordSuccess(db: BreakersDb, provider: string): Promise<CircuitBreakerRow> {
      const rows = await db.execute<CircuitBreakerRow>(sql`
        UPDATE provider_circuit_breakers
        SET state = 'closed',
            consecutive_failures = 0,
            opened_at = NULL,
            in_flight_at = NULL,
            updated_at = NOW()
        WHERE provider = ${provider}
        RETURNING *
      `);
      const r = rows[0];
      if (!r) throw new Error(`circuit_breakers.recordSuccess: no row for provider=${provider}`);
      return r as CircuitBreakerRow;
    }

    /**
     * Optimistic UPDATE: only transitions if state='open' AND in_flight_at IS NULL AND cooldown elapsed.
     * Returns rowCount (0 or 1) — the caller (router) checks the return to decide whether to dispatch.
     */
    export async function transitionToHalfOpen(db: BreakersDb, provider: string): Promise<{ transitioned: boolean }> {
      const rows = await db.execute<{ provider: string }>(sql`
        UPDATE provider_circuit_breakers
        SET state = 'half_open',
            in_flight_at = NOW(),
            updated_at = NOW()
        WHERE provider = ${provider}
          AND state = 'open'
          AND in_flight_at IS NULL
          AND opened_at < NOW() - ${COOLDOWN_INTERVAL}
        RETURNING provider
      `);
      return { transitioned: rows.length > 0 };
    }
    ```

| Boundary | Description |

| Router → repository | Router treats repo functions as primitives; correctness depends on each function being atomic at SQL layer |
| Concurrent UPDATEs on same row | Postgres row-level locking guarantees serialization |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-07-01 | T (Tampering) | Two concurrent recordFailure → counter race | mitigate | Single UPDATE with `consecutive_failures = consecutive_failures + 1` — Postgres row-level lock serializes; tests 5 + 8 verify counter correctness under back-to-back failures |
| T-06-07-02 | T | Two concurrent transitionToHalfOpen | mitigate | `WHERE state='open' AND in_flight_at IS NULL` — only ONE UPDATE matches; loser gets rowCount=0; test 14 proves this empirically |
| T-06-07-03 | E (Elevation) | recordSuccess called maliciously to clear breaker | accept | RLS exempts these tables (service-role only per D-07); routes never expose recordSuccess directly. Use-case calls them through the router only |
| T-06-07-04 | D (Denial of Service) | Stuck half-open with in_flight_at never cleared | mitigate | Both recordSuccess and recordFailure clear in_flight_at; if a router call crashes mid-flight, the breaker is stuck half-open until next dispatch — at which point the router sees state='half_open' AND in_flight_at IS NOT NULL and treats as open (per 06-06 test 13). Recovery: another `transitionToHalfOpen` sees state='half_open' (not 'open') and rowCount=0; ops can manually clear via `UPDATE ...
