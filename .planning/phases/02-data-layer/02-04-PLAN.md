  <action>
Add these bucket blocks under `[storage]` in `supabase/config.toml`. Add the inline TOML comments shown — they capture the defense-in-depth rationale that bucket caps are intentionally LOOSER than the route-level upload limit (1 MiB = 1_048_576 bytes; see Plan 08), so the route is the primary boundary and the bucket is a wider safety net:

```
# Defense in depth: route rejects >1 MiB (1_048_576 bytes) BEFORE any storage write.
# Bucket cap of 5 MiB is a wider safety net so a route bug cannot bypass the boundary.
[storage.buckets.plant-photos]
public = false
file_size_limit = "5MiB"
allowed_mime_types = ["image/jpeg", "image/png", "image/webp"]
objects_path = "./storage/plant-photos"

# Thumbnails are server-generated by sharp at <=512KB; cap is generous on purpose.
[storage.buckets.plant-thumbnails]
public = false
file_size_limit = "2MiB"
allowed_mime_types = ["image/jpeg", "image/png", "image/webp"]
objects_path = "./storage/plant-thumbnails"

# LGPD data exports are per-user zip/json bundles; can grow large for prolific users.
[storage.buckets.data-exports]
public = false
file_size_limit = "100MiB"
allowed_mime_types = ["application/zip", "application/json"]
objects_path = "./storage/data-exports"
```

Do not enable public buckets. After this change, the developer MUST run `supabase stop && supabase start` for the new bucket declarations to be materialized in local Storage. Document this requirement in the plan SUMMARY.
