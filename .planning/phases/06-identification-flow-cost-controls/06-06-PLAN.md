<objective>
TDD the identification router — the single most security-critical piece of cost-control logic in Phase 6. The router decides:
1. Which providers to try, in what order (primary → fallback)
2. When to skip a provider (open breaker; at-ceiling budget)
3. How long each provider call has (per-call timeout enforced via AbortController, capped at 30s; bounded by remaining-budget)
4. When to short-circuit (< 10s remaining means no fallover possible — bail out as provider_unavailable)
5. How to filter results (drop below min_confidence; cap at top-3)

Purpose: This is RESEARCH §Pattern + lines 807-891's verbatim shape. Per planner guidance, the router is a stateless function that takes `requestStartMs: number` from the use-case caller — the use-case owns time, the router does not. This makes it unit-testable with `vi.useFakeTimers()` (no DB, no real clock, no real providers — just typed test doubles).

Output: ~250-line router function + ~250-line unit test file covering 12+ behaviors via RED→GREEN→REFACTOR.
</objective>

    6. All results below threshold → router returns ok=true with empty `results.results` (zero-results case — IDENT-05 handled by use-case, but router itself returns ok=true with empty list; the use-case decides this is "success with zero results")

    7. requestStartMs = now-5000; budget remaining=45s → primary timeout = min(30000, 45000-2000) = 30000 (cap at 30s per-call)
    8. requestStartMs = now-25000; remaining=25s → primary timeout = min(30000, 25000-2000) = 23000 (capped at remaining-2s)
    9. requestStartMs = now-42000; remaining=8s < 10s → router short-circuits BEFORE calling any provider; returns ok=false, failureReason='provider_unavailable'

    **Breaker integration:**
    11. Primary breaker.state = 'open' AND opened_at < 60s ago → router skips primary, calls fallback; primary's `recordFailure` NOT called (skip is silent)
    12. Primary breaker.state = 'open' AND opened_at > 60s ago → router calls breakerRepo.transitionToHalfOpen('plant_id'), then dispatches; on success records success (closes); on failure records failure (re-opens)

    ```typescript
    // src/contexts/identification/application/identification-router.ts
    import {
      type IdentificationProvider,
      type IdentificationProviderResult,
      InvalidProviderResponseError,
    } from "@contexts/identification/domain/provider";
    import { type IdentificationFailureReason } from "@contexts/identification/domain/events";

    const TOTAL_BUDGET_MS = 50_000;
    const PER_CALL_CAP_MS = 30_000;
    const FALLOVER_MIN_REMAINING_MS = 10_000;
    const TIMING_OVERHEAD_MS = 2_000;
    const HALF_OPEN_COOLDOWN_MS = 60_000;

    export interface CircuitBreakerSnapshot {
      provider: string;
      state: "closed" | "open" | "half_open";
      openedAt: string | null;
    }

    export interface BreakerRepo {
      findByProvider(provider: string): Promise<CircuitBreakerSnapshot | null>;
      recordSuccess(provider: string): Promise<void>;
      recordFailure(provider: string): Promise<void>;
      transitionToHalfOpen(provider: string): Promise<void>;
    }

    export interface ProviderBudgetSnapshot {
      provider: string;
      purpose: "identification" | "care_guide";
      dailyCostCapCents: number;
      minConfidence: string | null; // numeric(3,2) — Drizzle returns string
    }

    export interface BudgetRepo {
      findByProviderAndPurpose(provider: string, purpose: "identification" | "care_guide"): Promise<ProviderBudgetSnapshot | null>;
      findUsageCounter(provider: string, purpose: "identification" | "care_guide", utcDate: string): Promise<{ estimatedCostCents: number } | null>;
    }

    export interface RouterDeps {
      providers: ReadonlyArray<IdentificationProvider>;
      breakerRepo: BreakerRepo;
      budgetRepo: BudgetRepo;
      now?: () => number; // for fake-clock injection — defaults to Date.now
    }

    export interface RouterInput {
      userId: string;
      photos: ReadonlyArray<{ buffer: Buffer; contentType: string }>;
      requestStartMs: number;
    }

    export type RouterResult =
      | { ok: true; result: IdentificationProviderResult }
      | { ok: false; failureReason: IdentificationFailureReason; provider: string };

    export async function dispatchIdentification(deps: RouterDeps, input: RouterInput): Promise<RouterResult> {
      const now = deps.now ?? Date.now;
      const utcDate = new Date().toISOString().slice(0, 10);
      let lastFailureReason: IdentificationFailureReason | null = null;
      let lastProvider = "";

      for (const provider of deps.providers) {
        lastProvider = provider.name;

        // (1) Breaker check (D-08 — read fresh, no cache; per-dispatch SELECT)
        const breaker = await deps.breakerRepo.findByProvider(provider.name);
        if (breaker?.state === "open") {
          const openedAtMs = breaker.openedAt ? new Date(breaker.openedAt).getTime() : 0;
          if (now() - openedAtMs > HALF_OPEN_COOLDOWN_MS) {
            await deps.breakerRepo.transitionToHalfOpen(provider.name);
            // proceed to dispatch — half-open admits ONE request
          } else {
            lastFailureReason = "breaker_open";
            continue;
          }
        }
        if (breaker?.state === "half_open") {
          // Half-open without explicit transition (e.g. set by another concurrent request)
          // — skip per OQ-1 in-flight semantics
          lastFailureReason = "breaker_open";
          continue;
        }

        // (2) Budget check (COST-05)
        const budget = await deps.budgetRepo.findByProviderAndPurpose(provider.name, "identification");
        if (!budget) {
          // No budget row = provider not configured for this purpose; skip silently
          continue;
        }
        const counter = await deps.budgetRepo.findUsageCounter(provider.name, "identification", utcDate);
        if (counter && counter.estimatedCostCents >= budget.dailyCostCapCents) {
          lastFailureReason = "cost_ceiling_reached";
          continue;
        }

        // (3) Time budget check (IDENT-18)
        const elapsed = now() - input.requestStartMs;
        const remaining = TOTAL_BUDGET_MS - elapsed;
        if (remaining < FALLOVER_MIN_REMAINING_MS) {
          lastFailureReason = lastFailureReason ?? "provider_unavailable";
          break;
        }

        // (4) Per-call timeout = min(30s, remaining - 2s)
        const timeoutMs = Math.min(PER_CALL_CAP_MS, remaining - TIMING_OVERHEAD_MS);
        const controller = new AbortController();
        const timer = setTimeout(() => controller.abort(), timeoutMs);

        try {
          const result = await provider.identify({
            photos: input.photos,
            userId: input.userId,
            signal: controller.signal,
          });
          clearTimeout(timer);

          // (5) Filter below min_confidence; cap at 3
          const minConf = Number(budget.minConfidence ?? "0.30");
          const filtered = result.results
            .filter((r) => r.confidence >= minConf)
            .sort((a, b) => b.confidence - a.confidence)
            .slice(0, 3);

          // Breaker: success → closed (closes from half_open or noop from closed)
          await deps.breakerRepo.recordSuccess(provider.name);

          return { ok: true, result: { ...result, results: filtered } };
        } catch (err) {
          clearTimeout(timer);
          const isTimeout = err instanceof DOMException && err.name === "AbortError";
          const isInvalid = err instanceof InvalidProviderResponseError;
          lastFailureReason = isTimeout
            ? "timeout"
            : isInvalid
            ? "invalid_response"
            : "provider_unavailable";
          await deps.breakerRepo.recordFailure(provider.name);
          // continue to next provider
        }
      }

      return {
        ok: false,
        failureReason: lastFailureReason ?? "provider_unavailable",
        provider: lastProvider,
      };
    }
    ```

    Key design notes:
    - The router is the ONLY place that constructs AbortController for provider calls
    - The router does NOT touch DB (`deps.breakerRepo` and `deps.budgetRepo` abstract DB access)
    - The router does NOT call `inngest.send` or `posthog.capture` — telemetry happens in the use-case (06-08)
    - The `now: () => number` injection point is the test seam — production passes `Date.now`, tests pass a counter
    - Half-open transition records the call to `transitionToHalfOpen` BEFORE dispatching; if dispatch succeeds the breaker closes via `recordSuccess`; if it fails, `recordFailure` re-opens

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `provider.identify()` → router | Provider response is untrusted; throws are caught and translated to internal failure reasons |
| Router → caller (use-case) | RouterResult is a closed discriminated union; INTERNAL_ONLY codes (`cost_ceiling_reached`, `breaker_open`) are router-internal and never become public ErrorCodes (use-case maps them to `provider_unavailable` via `errorResponse()` per COST-07) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06-01 | D (Denial of Service) | Hung provider holds Vercel function | mitigate | AbortController fires at min(30s, remaining-2s); test 10 proves timeout enforcement |
| T-06-06-02 | T (Tampering) | Provider returns inflated confidence | mitigate | min_confidence filter applied AFTER provider response; honest-AI invariant per UI-15 |
| T-06-06-03 | I (Information Disclosure) | failureReason leaks internal cause | mitigate | RouterResult exposes `failureReason: IdentificationFailureReason` (the union type from events.ts) which CAN include `cost_ceiling_reached`/`breaker_open`; use-case sanitizes via `errorResponse()` (errors.ts:69) before returning to client. INTERNAL_ONLY mapping is defense in depth here |
| T-06-06-04 | E (Elevation) | Cap evasion via short-circuit branch | accept | Router runs AFTER cap check in use-case (D-04); short-circuit returns provider_unavailable, NOT a free-pass — over-cap requests never reach the router |
| T-06-06-05 | T | Breaker write-without-lock race | mitigate | `recordSuccess`/`recordFailure`/`transitionToHalfOpen` atomicity is a repo concern (06-07); router treats them as primitives. Half-open in-flight semantics enforced via DB-side optimistic UPDATE |
| T-06-06-06 | T | Mock provider in stub mode bypasses real router behavior | accept | Stub mode is dev/CI only; production deploy is `IDENTIFICATION_PROVIDER_MODE=real` (Phase 1 D-05); routing logic applies identically to stub providers (test 1 + 2 use stubs) |
